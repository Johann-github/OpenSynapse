# 2026-11-13 Lighting

**Question:** Which lighting commands does Synapse 4 send to protocol-2.5 devices, how does
it pick between class 0x0F and class 0x03, and which zones does each device have?
**Evidence (source / tool):** Synapse 4 background-manager JavaScript (pretty-printed copy
in `~/re-work/synapse4/pretty/`: shared index module lighting helpers, `rzDevice25LedMatrix`,
`rzDevice25Legacy`, `rzDevice25LegacyHardwareEffect`, `rzDevice25ChromaEffect`, the
on-the-fly-macro module's LED helpers); 310 Synapse device manifests in
`~/re-work/synapse4/fetched/dm*/` (field `ledConfig.*.LedRegion[].RegionId`,
`rzDeviceConfig.rzDeviceName`); OpenRazer as cross-reference. Read by hand plus a small
local script that printed region IDs per product; nothing copied into the repo.

## Findings
- (observed) The base driver class builds 0F/02 as `[profile, region, effect, flags, rate,
  n, colours]` with data_size `6 + colour bytes`; 0F/04 brightness `[profile, region,
  value]`, percent → value with floor; reply value → percent with ceil.
- (observed) `rzDevice25LedMatrix` and `rzDevice25Legacy` override the effect method and
  send 03/0A with a separate effect enum (off 0, wave 1, reactive 2, breathing 3,
  spectrum 4, custom 5, static 6, …) and per-effect lengths; brightness via 03/03 with
  percent → value using ceil; LED 0 is replaced by the first ID from 03/89.
- (observed) `rzDevice25LegacyHardwareEffect` uses 03/02 (LED effect) + 03/01 (LED RGB);
  only one registry product uses it and it is flagged non-Chroma.
- (observed) DualLink mouse/keyboard, wireless keyboard and Oled subclasses do not
  override any lighting method.
- (observed) Frames and custom-frame effects use profile byte 0; the macro-LED helpers
  use profile 1 for brightness and default region 0 ("all region"), flags 0, rate 0 for
  effect restore.
- (observed) Manifest region IDs per product: 99 registry entries gained `zones`; common
  sets: logo only `[4]`, `[1, 4]` (wheel + logo), `[1, 4, 10]` (+ underglow), `[1, 4, 11]`
  (+ side stripe), keyboards `[5]` (backlight) or `[0]`.
- (inferred, OpenRazer) breathing flags 1 = one colour, 2 = two colours; wave flags =
  direction, rate 0x28; byte 0 0/1 = no store / var store.
