# 2026-11-09 Protocol 2.5

**Question:** Exact feature-report framing, status/transaction/timing rules, and the command table Synapse 4 uses for protocol-2.5 devices (focus: mice, Viper V3 HyperSpeed).
**Evidence (source / tool):** background-manager JS and product manifests (RE workspace outside the repo); prettier, ripgrep, a small node script listing every `[size, class, id]` constant with the description string passed alongside it.
Results: [[Protocol/Report Format 2.5]], [[Protocol/Commands 2.5]]. Device: [[Devices/Viper V3 HyperSpeed]].

## What was done
1. Prettified `index-*.js`, `otfm-*.js`, all `rzDevice25*.js`, `rzDevice30`, Protocol25 event parsers.
2. Located the protocol-2.5 base class (`rzDevice25`, subclass of generic `rzDevice`) and read its report builder, checksum, transaction-ID, send and read-back methods.
3. Resolved default timing/retry constants and the status-name table.
4. Extracted the command table (~430 constants) by script.
5. Read argument packing/parsing helpers for DPI, polling, power, wireless, buttons, profiles, lighting.
6. Compared subclasses (DualLinkMouse/Keyboard, Wireless/Mika keyboards, ChromaEffect) for transaction-ID routing.
7. Read `DeviceManifest_184_0.json` (Viper V3 HyperSpeed) for driver class and timing.

## Findings
- (observed) 90-byte report = OpenRazer layout; XOR CRC over bytes 2..87 at 88. Evidence: base class methods `_createDataSend`, `_calculateChecksum`.
- (observed) Request bytes 0, 2, 3, 4 always 0. Reply validated by echo of bytes 1, 6, 7; reply CRC ignored. Evidence: `_getUSBTransferInResult`.
- (observed) Transaction ID = rolling counter 0..30 per device object; routing bits 0x80 / 0xF0 for keyboards; DualLinkMouse adds 0x80 only for pairing-mode and device-scan. Evidence: `_getTransactionId` overrides.
- (inferred) Upper TID bits address the target behind a receiver.
- (observed) Defaults 5/5/5 ms, maxRetryIn 10 (hard cap), maxRetryOut 20; Viper manifest 25 ms each.
- (observed) `deviceCommandEnum` is an IPC category enum (8 / 14), not the HID command table.
- (observed) Polling: legacy code table on 00/05; HyperPolling bitmask on 00/40 with profile byte.
- (observed) DPI: 04/05 & 04/85 `[storage, X, Y, Z]` u16 BE; stages 04/06 & 04/86, 7-byte entries.
- (observed) Battery 07/80 raw 0–255; charging 07/84; low-battery threshold 07/01; sleep timer 07/03 u16.
- (observed) Button remap 02/0C `[profile, button, mode, function, len, data]`; enums for button IDs / function types present.
- (observed) Viper V3 HyperSpeed: `rzDevice25DualLinkMouse`, interface 0, isDualLink, no Chroma, event parser type 1.

## Open questions

- Function-specific data bytes for button assignment — built outside background-manager.
- Unit of "Time to Sleep" (07/03) — seconds per OpenRazer, unconfirmed.
- Viper V3 HyperSpeed: polling command (00/05 vs 00/40), DPI range, onboard profile count, wired-mode PID.
- Does firmware check the CRC? Which interface delivers event reports?
- Meaning of the extra input (82, 16) in the Viper LED input map.
